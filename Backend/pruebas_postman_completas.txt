====================================================================
PRUEBAS FUNCIONALES - PROYECTO VETERINARIA (Postman)
====================================================================
Base URL: http://localhost:4000

NOTA GENERAL: los IDs entre <> (ej. <IdCliente>) los tenes que
reemplazar por un ID real que te devuelva la base o una respuesta
anterior. El orden de abajo esta pensado para que primero crees los
datos "base" (Cliente, Mascota, Animal, Rol) y despues los que
dependen de ellos (Cita, Adopcion, Postulacion, etc.)

Para cada request, anota: status code recibido, y si el mensaje
tiene sentido con lo que pediste. Cualquier 500 (error de servidor)
o comportamiento raro, anotalo para revisarlo.


====================================================================
0) SALUD / DEBUG
====================================================================
GET /api/health
-> Esperado: 200, { status: "ok", db: "conectado" }

GET /api/debug-conexion
-> Esperado: 200, { Servidor, BaseDeDatos, SPID }

1) AUTH
====================================================================
POST /api/auth/login
Body:
{
  "correo": "algun_correo_valido@ejemplo.com",
  "contrasena": "la_contrasena_real"
}

Credenciales para admin
correo:admin@vetacre.com
contra:Prueba123!

Credenciales para veterinario
correo: veterinario@vetcare.com
contra: Prueba123!

Credenciales para recepcionista
correo:recepcionista@vetcare.com
contra: Prueba123!

Credenciales para encargado de refugio
correo:refugio@vetcare.com
contra:Prueba123!

-> Esperado: 200, { token, usuario: { id, nombre, correo, rol } }
   (probar con un Administrador, un Empleado y un Cliente si tenes
   credenciales de los 3, para confirmar que detecta el rol bien)

POST /api/auth/login (credenciales incorrectas)
Body:
{
  "correo": "no_existe@ejemplo.com",
  "contrasena": "cualquiera"
}
-> Esperado: 401, "Correo o contraseña incorrectos"

POST /api/auth/login (faltan campos)
Body: {}
-> Esperado: 400, "Correo y contraseña son obligatorios"

2) CLIENTES (dueños)
====================================================================
GET /api/clientes
-> Esperado: 200, lista de clientes

GET /api/clientes/buscar?nombre=ana
-> Esperado: 200, lista filtrada por nombre (parcial, sin importar mayúsculas)

POST /api/clientes
Body:
{
  "NombreCompleto": "Cliente de Prueba",
  "Cedula": "1234567890",
  "Telefono": "88889999",
  "CorreoElectronico": "clienteprueba@correo.com"
}
-> Esperado: 201, "Cliente creado correctamente"
-> GUARDATE el IdCliente que te devuelva GET /api/clientes para usarlo abajo

POST /api/clientes (cedula duplicada, repetir el body de arriba)
-> Esperado: 409 o error de UNIQUE, no debería dejar duplicar cedula

GET /api/clientes/<IdCliente>
-> Esperado: 200, datos del cliente creado

aca para ver el id de cliente debes listarlos para saber

PUT /api/clientes/<IdCliente>
Body:
{
  "NombreCompleto": "Cliente de Prueba Editado",
  "Cedula": "1234567890",
  "Telefono": "88880000",
  "CorreoElectronico": "clienteprueba@correo.com"
}
-> Esperado: 200, "Cliente actualizado correctamente"

GET /api/clientes/99999  (id que no existe)
-> Esperado: 404

DELETE /api/clientes/<IdCliente>  (probar al final, cuando ya no lo necesites para otras pruebas)
-> Esperado: 200, "Cliente eliminado" (o 409 si tiene mascotas/citas asociadas)

GET /api/mascotas/<IdMascota>

-> Esperado: 200 (o 409 si tiene citas asociadas)

4) CITAS
====================================================================
GET /api/citas
-> Esperado: 200, lista con nombre de mascota y dueño

GET /api/citas/fecha/2026-08-25  (formato YYYY-MM-DD)
-> Esperado: 200, citas de ese día

POST /api/citas
Body:
{
  "Fecha": "2026-09-15",
  "Hora": "10:00",
  "Motivo": "Consulta general",
  "IdMascota": <IdMascota>
}
-> Esperado: 201, "Cita agendada correctamente"
-> Debería llegarte un correo al dueño de la mascota
-> GUARDATE el IdCita

POST /api/citas (mismo Fecha+Hora que la de arriba, repetir el body)
-> Esperado: DEBE RECHAZAR (esto es justo lo que veníamos probando -
   avisame si te deja crear la segunda, es el bug que seguimos
   investigando)

POST /api/citas (Hora fuera de rango, ej "20:00")
-> Esperado: 400, "Las citas solo se pueden agendar entre las 8:00 a.m. y las 4:00 p.m."

POST /api/citas (IdMascota que no existe)
-> Esperado: 400, "La mascota no existe."

GET /api/citas/<IdCita>
-> Esperado: 200

PUT /api/citas/<IdCita>
Body:
{
  "Fecha": "2026-09-15",
  "Hora": "11:00",
  "Motivo": "Consulta general editada",
  "Estado": "Pendiente",
  "IdMascota": <IdMascota>
}
-> Esperado: 200


PATCH /api/citas/<OTRO_IdCita>/cancelar   (usar una cita en estado Pendiente)
-> Esperado: 200, "Cita cancelada correctamente"
-> Debería llegar correo avisando la cancelación
-> Probar también con una cita que falte MENOS de 1 hora para confirmar
   que bloquea con el mensaje de "falta menos de 1 hora"

DELETE /api/citas/<IdCita>  (probar al final, con una cita sin atención asociada)
-> Esperado: 200 (o mensaje de que no se puede si tiene atención veterinaria asociada)

7) ADOPCIONES
====================================================================
(Necesitas un IdCliente y un IdAnimalRefugio con Disponible=true)

POST /api/adopciones
Body:
{
  "CondicionVivienda": "Casa con patio",
  "TieneMascotas": false,
  "MotivoAdopcion": "Quiero darle un hogar",
  "IdCliente": <IdCliente>,
  "IdAnimalRefugio": <IdAnimalRefugio>
}
-> Esperado: 201
-> GUARDATE el IdSolicitud

GET /api/adopciones
-> Esperado: 200

GET /api/adopciones/pendientes
-> Esperado: 200, solo las que están en estado Pendiente

GET /api/adopciones/reporte
-> Esperado: 200, reporte "Adopciones realizadas"

PATCH /api/adopciones/<IdSolicitud>/aprobar
-> Esperado: 200, y el animal debería pasar a Disponible=false

--- Para probar rechazar/cancelar/devolver, crea OTRAS solicitudes
    nuevas por separado (una solicitud ya aprobada no debería poder
    rechazarse/cancelarse de nuevo):

PATCH /api/adopciones/<OTRA_IdSolicitud_2>/rechazar
-> Esperado: 200

PATCH /api/adopciones/<OTRA_IdSolicitud_3>/cancelar
-> Esperado: 200 (solo debería funcionar si está en estado Pendiente)

PATCH /api/adopciones/<IdSolicitud_aprobada>/devolver
-> Esperado: 200, y el animal debería volver a Disponible=true

DELETE /api/adopciones/<IdSolicitud>  (al final, con alguna de prueba)
-> Esperado: 200
